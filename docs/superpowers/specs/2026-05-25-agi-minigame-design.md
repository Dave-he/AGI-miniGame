# AGI-miniGame 设计文档: 基于玩家行为与实时生成的游戏元宇宙引擎

## 1. 核心体验愿景
打造一个“基于玩家行为与实时生成的游戏元宇宙引擎”。游戏初始处于极简状态，通过玩家的探索、战斗与主动干预，AGI 实时生成改变游戏规则的 DSL（领域特定语言），实现游戏类型、技能、物理法则的无限演化与叠加。

## 2. 核心游戏循环 (Gameplay Loop)
1. **生存与碰撞**：玩家在一个基础网格/空间中控制实体，通过“移动”与世界中的其他实体发生“碰撞”。
2. **模因收集**：碰撞会掉落“模因碎片”（Memes，代表如 [火]、[速度]、[生命]、[重力] 等基础概念）。
3. **极速拼装（高压态）**：在游戏**不暂停**的实时危机下，玩家将收集到的碎片拖入“星图/编译槽”进行组合（如：[火] + [速度] + [创造]）。
4. **AGI 实时生成**：系统将碎片组合及当前战斗上下文发送给大语言模型，AGI 瞬间输出一段定义了新规则或技能的 **DSL (领域特定语言)**。
5. **引擎执行与突变**：底层 Rust 引擎 (cocos4-rust) 毫秒级解析 DSL，世界瞬间发生改变（生成火球、重力反转、怪物变异等）。

## 3. 世界运转与世代系统 (The Multiverse Structure)
游戏采用“文明演化 + 个人飞升”的三层架构来容纳 AGI 生成的无限可能：
*   **Layer 1: 个人卡牌（芯片槽）**：AGI 生成的具体技能（如“发射火球”）化为卡牌，玩家最多装备 5 张。可随时在战斗中插拔、替换，应对当前危机。
*   **Layer 2: 世界法则（无尽叠加）**：AGI 生成的全局规则（如“全图重力-50%”或“实体死后分裂”）会永久叠加在当前纪元的世界中，导致环境越来越复杂、混沌。
*   **Layer 3: 纪元更迭（大坍缩）**：当世界法则叠加到阈值（或玩家主动触发），世界进行重构进入下一纪元。旧纪元的部分核心法则会被压缩为新纪元的“历史遗迹（特殊 Buff/Debuff）”，保证游戏既有历史沉淀，又不会因为逻辑冲突而彻底崩溃。

## 4. 技术架构与 DSL 设计
基于 `cocos4-rust` 的高性能 ECS 架构，实现一套**综合型微型 DSL**，作为 AGI 与引擎的通信协议。

### 4.1 综合 DSL (AGI-Script) 核心能力
DSL 必须具备以下三种原语能力：
*   **事件与动作 (Event-Action)**：定义基于时间的触发器和行为。
    *   *例: `On(Collide, Player, Enemy) -> Apply(Damage, 10)`*
*   **规则修改 (Rule-Modifier)**：修改全局物理或游戏循环参数。
    *   *例: `Set(World.Gravity, -9.8)`*
*   **实体变异 (Entity-Mutation)**：动态挂载组件或转换实体形态。
    *   *例: `Attach(Player, Component.Aura(Fire, 5))`*

### 4.2 架构流转图
```
[ 玩家拖拽碎片 ] -> (触发) -> [ TypeScript 逻辑层 ] 
       |
       v
[ 组装 Prompt (含玩家画像+当前战场上下文) ]
       |
       v
[ AGI 大模型接口 (并发, 极速响应) ]
       |
       v
[ AGI 输出 DSL 代码 (如: On(Timer, 1s) -> Spawn(Fireball)) ]
       |
       v
[ Rust 引擎层 (DSL 解析器) ] -> (编译为 ECS 组件/系统) -> [ 世界瞬间突变 ]
```

## 5. 关键技术挑战与应对 (Risk & Mitigation)
*   **挑战 1：AGI 的延迟导致玩家死亡**。
    *   *应对*：在碎片投入编译槽时，给玩家提供一个短暂的“护盾”或“编译充能”动画表现，掩盖网络延迟；使用流式输出 (Streaming) 提前解析部分 DSL。
*   **挑战 2：DSL 的安全与防崩溃**。
    *   *应对*：Rust 层的解析器必须是强沙盒化的（Sandbox），对于引发死循环或除零错误的 DSL，要有容错机制，将其转化为一次“失败的变异（爆炸或反噬）”而不是游戏崩溃。
*   **挑战 3：生成结果不可控**。
    *   *应对*：给 AGI 提供的 Prompt 中必须严格限制输出格式，并提供当前世界 ECS 组件的白名单字典。
